# Umamusume Knowledge Base

This folder is the Umamusume (Uma Musume: Pretty Derby) reference library used by **LilyAi**. Everything is plain Markdown so an AI can search it, open the right file, and answer questions without reading the whole repository. This README is a map: it says what each directory is, what is inside, and when to use it.

## Quick lookup

| Question is about... | Go to |
|----------------------|-------|
| A specific character (aptitudes, objectives, versions, birthday) | `Character/<Name>.md` |
| What a slang term, acronym or mechanic means | `Glossary/Glossary.md` |
| What a skill does or who owns a unique skill | `Skill/skill.md` |
| Support card stat bonuses, hints, unique effects | `Support Cards/` |
| How to play, build, plan a career, race mechanics, PvP, club quota | `Guide/` (start at `Guide/Readme.md`) |
| What a category is called and numbered (skill tiers, running styles, ground names, stats, support types) | `Taxonomy/Taxonomy.md` |

## Character/

One Markdown file per playable Umamusume, named with underscores, for example `Believe.md`, `Special_Week.md` or `Mejiro_McQueen.md`. Each file is an encyclopedia-style profile. It opens with an infobox (Japanese name, voice actor, birthday, height, dorm, strengths and weaknesses), then Overview, Background, in-game profile trivia, and the real-life racehorse counterpart with its race record. The game-data half lists every playable version of the character, shared aptitudes (Turf, Dirt, distances, running styles with ranks), career objectives by turn, and stat growth bonuses. A Gaps section flags what is still empty, and Sources lists the GameTora links and image URLs. Many files were generated by a script, so some sections say "Not filled in yet". Use this directory whenever a question names a character. Open the file by name instead of searching the whole folder.

## Glossary/

A single file, `Glossary.md`, with about 190 terms condensed from the uma.guide glossary. It is a three-column table: Term, Also Known As (nicknames, abbreviations, Japanese names) and Definition. It covers racing mechanics (Position Keep, Spurt Rate, Rushed, Dueling), career terms (Bond, Spark, Inspiration, Turns), game modes (Champions Meeting, Team Trials, League of Heroes), running styles, outfit nicknames, team archetypes such as Chariot and Bermuda Triangle, and many community slang words. Some entries also give a short skill effect. Use it first when a user writes an unfamiliar abbreviation like "CM", "KFC", "TT" or "Wincon", or asks what a term means, because it translates community shorthand into plain definitions and points to the right concept.

## Guide/

The largest directory and the strategy library. `Guide/Readme.md` is its own detailed index, describing every file, so read it before opening anything else here. It also documents how LilyAi supports the Umakraft clubs: account linking, the 150m monthly fan quota, the daily DM report and the Leaderboard. The subfolders are: Umamusume Global Quickstart Guide, Umamusume New Player FAQ and Uma Musume Guide For Absolute Beginners (onboarding); Career (the start-of-career interview workflow plus scenario guides such as URA Finale, Unity Cup, Grand Live and Trackblazer); AdvanceCareerGuide and AdvanceGameplayGuide (deep unified references for training, stats, inheritance, skills, PvP and resources); CommunityGuide (Guide1 to Guide9, community write-ups on support card ranking, race mechanics, Champions Meeting and later scenarios); Uma Musume Legacies and Affinity (inheritance and compatibility tables); RaceList and Race Mechanics Handbook (race calendars and race engine basics); Champions Meeting; and Team Trials PvP Scoring System. Several files are very large, so search them by keyword rather than reading top to bottom.

## Skill/

A single file, `skill.md`, built from Game8's skill lists. It contains three big tables: Unique Skills (each character's exclusive skill, with the character and outfit that owns it), Rare Skills (gold skills) and Normal Skills (white skills), plus the Negative (purple) skills gained by losing races. Every row has four columns: Skill Name, Skill Type (Velocity, Acceleration, Speed - Other, Green, Recovery, Debuff, Negative, Unique), Skill Activation Requirements, and Acquisitions (innate to a character, bought with Skill Points, an upgrade of another skill, or removal cost). The top of the file explains inheritance of unique skills. Use it to answer what a skill does, when it triggers, what type it is, and how to obtain or upgrade it.

## Support Cards/

The support card database, split by rarity (SSR, SR, R) and by level of detail. `SupportCardList.md` is the small index. `SSR.md`, `SR.md` and `R.md` are compact tables of stat bonuses per card, grouped by type (Speed, Power, Stamina, Guts, Wit, Group, Friend; the wiki calls Friend "Pal"). `SSR-Details.md`, `SR-Details.md` and `R-Details.md` hold the long per-card data: hints, unique effects and events. The Details files are very large (SSR-Details is the biggest file in the repo), so search them by card name instead of loading them fully. The data comes from umamusu.wiki and was generated by `tools/build_support_cards.py`. Use this directory for deck building, comparing cards, and checking what a specific card gives.

## Taxonomy/

A single file, `Taxonomy.md`, that names and numbers the categories used across this library and the simulator. It covers the race basics (stats, running styles, surfaces, distance types, ground, aptitudes, moods, phases), support card types and rarities, and the skill taxonomy: tier (normal, rare, unique, inherited unique, negative), effect (velocity, acceleration, recovery, positioning, passive, debuff), scope, level mark, trigger context and simulator status. It also lists the kinds of things that have ids (trainee, support card, skill, course...), the mechanics domains, and the naming rules, including where sources disagree (for example the ground names, where Global's Firm is upstream's "good"). The code version is `Taxonomy.py` in this folder. Use this file when a question is about what a category is called, how it is numbered, or why two files name the same thing differently.

## Notes for AI readers

- Prefer opening a single named file (a character, `Glossary.md`, `skill.md`) over scanning directories.
- For anything strategic, read `Guide/Readme.md` first, then jump to the file it recommends.
- Data comes from third-party sites (GameTora, Game8, uma.guide, umamusu.wiki, uma.moe) and can lag behind game updates. Game materials are copyright Cygames, Inc.
